## Findings
- **Overlay swap area on the map and province screens holds OVL0 file 0x0000-0x09A0 only** (0x9A0 bytes, byte-exact), followed by zeros
  (both snapshots). OVL0 file 0x09A0 starts a new function (`55 8b ec 83 ec 0e`), i.e. a **different section**. So the "map section"
  is 0x0000-0x09A0, not 0x0000-0x51A0. OVL_MAP.clean.asm covers several sections disassembled as one blob.
- Resident data DS=1686: the DS:5700 area matches OVL0 file 0xB400+ 256/256 in both snapshots.
- Manpower 5279 (0x149F) of Narbonensis is at **DS:5574** in the snapshot (only resident-data hit). Code next to the province builder
  (EXE ~0x7250) does `mov bx,[bx+0xC114]; shl bx,1; push [bx+0x5222]` before strcat into DS:AC60: a lookup through DS:C114
  (14-byte records?) into a word table at DS:5222. UNVERIFIED reading, but a good place to find the province record.

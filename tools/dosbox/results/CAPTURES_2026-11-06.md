## Findings
- **CBM table 0 = keep current table: VERIFIED.** Race strip rows 130-199 = GALLERY2 with table 3: 90.4% (rest is the chariot sprite);
  with table 0: 2.0%. GALLERY1 with table 3: 99.5%.
- **OVL0 is a real overlay with a swap area at 1331:0000** (= 0823:B0E0, right after the EXE image). During the race it holds
  OVL0 file 0x051A0-0x08540 (13,216 B, the race code); on the map (round-1 capture) it held file 0x00000-0x009A0+. OVL0 file
  0xB400+ is the data segment DS=1686 (resident). So OVL0's code (file 0x0000-0xB400) must be split into sections and each
  disassembled with origin 1331:0000 (or the segment the overlay manager uses). The section table is still to be found.
- Race data resident: RACEDAT (linear 0x49412), MEDDAT (0x4EB82), RACE2DAT (0x56672), CN3B (0x5C4E0), CN3A (0x218CE).
- **Clean disassembly misses traced code:** 0x0000-0x0034 (timer ISR), 0x8840-0x8856, 0x907B-0x9123 (all executed in the race).
- Gotcha: MEMDUMPBIN wraps inside one segment. 'MEMDUMPBIN 0000:0000 A0000' gives the first 64 KB ten times. Dump per 64 KB segment
  (tools: C:\DOSBox-X\hunt\snap.ps1 on Erik's PC).
